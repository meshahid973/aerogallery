# AeroGallery design

Use the original Windows Photo Gallery layout as the functional reference: compact command toolbar, folder navigation, thumbnail surface, address/search controls and status bar. Use glass only on the command band, glossy split gradients on controls, recessed inputs, ice-white photo surfaces and public-domain Tango icons. Do not add decorative dashboard cards, oversized headings, simulated photos, or unrelated text.

Colors, lighting and geometry belong in `src/styles/tokens.css`; shared control treatments in `src/styles/materials.css`; reusable controls in `src/components/aero`; gallery-specific layout in its CSS module. Add new states to the existing material system instead of replacing it per feature.

Reference: [original Windows Photo Gallery screenshot](https://betawiki.net/wiki/Windows_Photo_Gallery), [2007 Photo Gallery reconstruction](https://www.viksoe.dk/code/photothing.htm), [2006 Photo Gallery overview](https://arstechnica.com/information-technology/2006/05/4018/), [Windows UX guide](https://learn.microsoft.com/en-us/windows/win32/uxguide/guidelines), [icon design](https://learn.microsoft.com/en-us/windows/win32/uxguide/vis-icons). Use the previous [Frutiger theme](https://github.com/gelogonza/frutiger-obsidian-theme) and [7.css](https://github.com/khang-nd/7.css) as material references, not runtime dependencies.

On Windows, the app owns one Aero caption bar with native Tauri drag, resize, minimize, maximize/restore and close actions. Other platforms retain their system decorations. Windows uses native Acrylic behind the translucent command band, with an opaque fallback on other platforms and reduced-transparency mode. No nested window frame, decorative wallpaper, or full-window CSS blur. The gallery, sidebar and footer remain opaque with single separators. Loading belongs in the status strip only. Preserve keyboard focus, reduced motion/transparency and high-contrast support. New photo features should reuse the existing shell.

Keep the photo grid virtualized with a bounded viewport window; do not add pagination controls or eagerly decode off-screen images. Preserve selection and scroll during filesystem updates.

The viewer uses a single photo stage and a compact glossy playback strip based on Windows Photo Gallery. Use existing glass and control materials, period Tango playback icons and simple functional glyphs; no secondary framed window. Rotation is a view transform only. Fullscreen uses the real window state, hides the custom caption and restores the gallery on exit.

Appearance uses hue-derived material tokens: Aero (sky blue), Aqua (rounded water-gloss), Aurora (violet and green reflection), Frost (silver-blue). Theme choice and glass density persist locally. Reflective gradients and static textures are confined to chrome, not the photo stage. The supplied CSS references informed split highlights, layered bevels, accent shades and glossy scrollbars; their website-specific layout, animations, external URLs and fonts are not bundled.
